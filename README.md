# BARBER CULT

Адаптивный концепт премиального барбершопа в Алматы для портфолио веб-разработчика. Editorial / brutalist: угольно-чёрный фон, кремовая типографика, киноварный акцент, крупный Oswald, Manrope и фотокомпозиции без одинаковых карточек.

**Demo Project.** Бренд, команда, цены, расписание, отзывы и локация вымышлены. Реальных контактов, платежей, бронирований, отправки заявок и аналитики нет. Это прямо обозначено в интерфейсе.

## Запуск

Нужен **Node.js 22.6+** (рекомендуется актуальная LTS-версия) и npm. Все команды выполняются из корня этого проекта.

```bash
npm install
npm run dev
```

Открыть адрес, напечатанный Vite в терминале, обычно `http://localhost:5173`.

```bash
npm run build
npm run preview
```

Сборка запускает TypeScript, затем создаёт production-файлы в `dist/`. Для публикации подойдёт любой статический хостинг. Сервер приложения и секреты не нужны. Публикация не выполнялась.

`.npmrc` направляет кеш npm в `.npm-cache/` внутри проекта. Сгенерированный после установки `package-lock.json` следует сохранить в репозитории; для последующих воспроизводимых установок использовать `npm ci`.

## Стек

- Vite, React 19, TypeScript со строгими проверками.
- Tailwind CSS 4 через `@tailwindcss/vite`; собственные CSS-композиции и адаптивные стили.
- Lucide React, иконки импортируются по отдельности.
- Oswald Variable и Manrope Variable через Fontsource: шрифты включаются в сборку, Google Fonts не используется.
- Node Test Runner для логики записи; Playwright и axe-core для браузерных проверок.

## Что реализовано

- Sticky-навигация, активный пункт раздела, мобильное меню, якоря, ссылка пропуска навигации и возврат наверх.
- Hero, философия, интерактивный прайс в тенге, три вымышленных мастера, фотогалерея, демоотзывы, CTA, FAQ, контакты и футер.
- Услуга из прайса и мастер из профиля автоматически выбираются в форме.
- Двухшаговая запись: услуга, мастер, дата, время → имя, телефон, подтверждение деморежима.
- Даты считаются по `Asia/Almaty`: от завтра до 30 дней вперёд. Слоты демонстрационные; это не информация о реальной доступности.
- Проверка обязательного времени, допустимого диапазона и корректности даты, имени, телефона и чекбокса. Ошибки связаны с полями через ARIA; фокус переходит к первому ошибочному полю.
- Возврат на первый шаг сохраняет выбор и поля, экран результата показывает итог. Закрытие формы сбрасывает все введённые данные.
- Фильтры галереи и полноэкранный просмотр. Стрелки клавиатуры переключают фотографии, Escape закрывает окно. Кнопки доступны на сенсорном экране.
- Переключение демоотзывов; нативные `details` / `summary` для FAQ.
- Диалоги «О проекте» и «О данных и приватности».

## Доступность и адаптивность

Семантические `header`, `nav`, `main`, `section`, `article`, `footer`, связанная иерархия заголовков, подписи полей, видимый фокус, альтернативный текст изображений. Нативные `<dialog>` изолируют фокус, делают страницу под модальным окном неактивной и восстанавливают фокус после закрытия. Анимация учитывает `prefers-reduced-motion`.

Стили предусмотрены для ширины от 320 px до широкого десктопа. При отключении изображений показываются графические заглушки, сохраняя размеры блоков. Браузерная проверка этих состояний описана в `tests/site.spec.ts`; статус фактического запуска — ниже.

## Данные и приватность

Форма работает исключительно в состоянии React. В ней нет `fetch`, серверных действий, отправки email/SMS, cookies, localStorage или sessionStorage. Имя и телефон не включаются в адрес страницы. После закрытия формы либо обновления страницы они исчезают. Для демонстрации можно указать вымышленные данные.

Единственный внешний ресурс во время просмотра — фотографии с `images.unsplash.com`. Этот сервис получает стандартные технические данные запросов изображений, включая IP-адрес; значения формы ему не передаются. Шрифты и код после сборки загружаются с того же хоста, где размещён сайт.

## Фотографии и производительность

Фотографии используются для иллюстрации настроения; люди на фото не являются сотрудниками вымышленного бренда. Источники перечислены в [ASSETS.md](./ASSETS.md).

- `srcset` и `sizes` выбирают размер изображения под экран.
- Главная фотография имеет `fetchPriority="high"`; остальные загружаются лениво.
- Размеры контейнеров резервируются заранее.
- Форма записи выделена в отдельный JS-чанк через `React.lazy`.
- Иконки и шрифты входят в сборку; тяжёлых библиотек анимации нет.
- Hero и фотографии могут отображаться только при доступе к Unsplash. При ошибке загрузки используется оформленная заглушка.

## Проверки

Логика формы, без установки сторонних пакетов:

```bash
npm test
```

Браузерные проверки после установки зависимостей:

```bash
npx playwright install chromium
npm run test:e2e
```

Playwright сам запускает dev-сервер на `http://127.0.0.1:4173`. Сценарии проверяют запись и ошибки полей, отсутствие отправки данных, перенос выбора мастера, восстановление фокуса, меню, галерею, FAQ, отзывы, отсутствие горизонтального переполнения на 320–1920 px, недоступность изображений и автоматические правила доступности axe. Автоматический аудит не заменяет проверку со скринридером.

## Структура

```text
src/
  App.tsx                Разделы сайта и общие состояния интерфейса
  data.ts                Контент, цены, мастера, фотографии и FAQ
  booking.ts             Даты и независимая валидация формы
  components/
    Booking.tsx          Два шага записи и экран подтверждения
    Dialog.tsx           Нативный диалог, Escape и восстановление фокуса
    Photo.tsx            Адаптивные изображения и fallback
  styles.css             Tailwind и авторская адаптивная композиция
  main.tsx               Точка входа и локальные шрифты
public/
  favicon.svg            Авторская монограмма
tests/
  booking.test.mjs       Исполняемые тесты логики
  site.spec.ts           Браузерные сценарии
```

Контент изменяется в `src/data.ts`, цветовые переменные — в начале `src/styles.css`, метаданные — в `index.html`. Подключение реальной записи не входит в демо: для него потребуются отдельный backend, актуальное расписание и соответствующая обработка персональных данных.
